Spring Boot · React · Claude tool use

Market Dashboards

A small full-stack demo: a React prompt box calls a Spring Boot backend that runs a Claude tool-use agent loop. Each market dashboard is a tool; the prompt decides which dashboards Claude shows.

Java 21 Spring Boot 4.1.1 React + Vite Finnhub POST /api/dashboard

What it does

You type a prompt — for example Show me the biggest losers and the most shorted stocks — and hit Show Dashboards. Claude reads the prompt, calls the dashboard tool(s) you asked for, and the matching tables appear. Three dashboards are available: Most Shorted Stocks, Day Losers, and Top Mutual Funds. Every row is a StockRow: symbol, name, price, day change %, and the dashboard's signature metric.

Price and change % are pulled live from Finnhub. The signature metric (short % of float, average volume, YTD return) is curated, because Finnhub's free tier does not expose it — and the 5-symbol membership of each dashboard is curated too.

How it flows

One prompt can become several jobs. Claude decides which dashboard tools to call — zero, one, or more — and the loop runs each, then hands the results back until Claude is done.

most_shorted
heavily shorted stocks
day_losers
biggest decliners
top_mutual_funds
top-performing funds
DashboardServiceImpl — the tool-use loop runs whichever tools Claude picked

Design

A common DataService interface has three implementations, one per ServiceType (MOST_SHORTED, DAY_LOSERS, TOP_MUTUAL_FUNDS). Spring injects all of them into a ServiceFactory, which indexes them by type so a caller asks for a provider by role rather than by class. 

// Claude picks the tools; the factory resolves each one to a provider
DashboardController  POST /api/dashboard
        ↓
DashboardServiceImpl → tool-use loop → ServiceFactory.get(type) → DataService
                                                     ├─ MostShortedServiceImpl
                                                     ├─ DayLosersServiceImpl
                                                     └─ TopMutualFundsServiceImpl

DashboardServiceImpl exposes the three providers as tools, sends the prompt to Claude, runs whichever tools Claude requests, feeds the results back, and repeats until Claude stops calling tools. Each provider pulls live quotes through FinnhubClient, which degrades to a curated fallback price on any failure so a dashboard always renders.

The endpoint

curl -X POST http://localhost:8080/api/dashboard \
  -H 'Content-Type: application/json' \
  -d '{"prompt":"show me the biggest losers and the most shorted stocks"}'

Response (trimmed):

{
  "prompt": "show me the biggest losers and the most shorted stocks",
  "mostShorted":    [ /* 5 rows */ ],
  "dayLosers":      [ /* 5 rows */ ],
  "topMutualFunds": [ /* empty: not requested */ ]
}

Run it locally

  1. Backend — starts on port 8080. Needs two keys in the environment. 
    cd marketsdata_backend
export ANTHROPIC_API_KEY=sk-ant-...
export FINNHUB_API_KEY=...
./mvnw spring-boot:run
  2. Frontend — starts on port 5173. Vite proxies /api to :8080, so the browser sees one origin and no CORS setup is required. 
    cd marketsdata_frontend
npm install
npm run dev
  3. Open http://localhost:5173, type a prompt, and click Show Dashboards. A table appears for each dashboard Claude chose.
